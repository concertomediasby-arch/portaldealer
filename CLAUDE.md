# Concerto Dealer Portal — Panduan Proyek (untuk Claude Code)

Portal informasi produk (katalog digital) untuk dealer & distributor **Concerto Audio Indonesia (CAI)**.
Menampilkan brand yang dinaungi beserta produk, spesifikasi, media, dan spec sheet PDF. **Harga yang boleh tampil hanya harga jual umum (SRP)** — sejak 2026-10 atas keputusan pemilik; harga dealer/modal/diskon tetap tidak boleh masuk portal.

## Arsitektur

- **Satu file statis: `index.html`** — berisi seluruh HTML, CSS, JavaScript, dan data katalog dalam satu dokumen. Tidak ada build step, tidak ada server sendiri, tidak ada dependency npm. Satu-satunya data dinamis adalah **stok produk** di Supabase (lihat bagian *Sistem stok*).
- Dependency eksternal via CDN (dimuat saat runtime di browser):
  - Google Fonts: **Sora**, **Inter**, **JetBrains Mono**
  - **jsPDF** (cdnjs) — untuk generate spec sheet PDF per produk.
  - **supabase-js v2** (jsdelivr) — baca/tulis stok + realtime.
- Logo CAI di-embed sebagai **data URI base64** di dua konstanta JS: `LOGO_WHITE` (untuk latar gelap) dan `LOGO_NAVY` (untuk latar terang). Cari `const LOGO_WHITE` / `const LOGO_NAVY` di dalam `<script>`.

## Menjalankan

Buka `index.html` langsung di browser (double-click), atau jalankan server statis lokal:

```bash
python3 -m http.server 8000   # lalu buka http://localhost:8000
```

Tidak perlu instalasi apa pun.

## Model data (paling sering diedit)

Data katalog ada di array **`BRANDS`** di dalam `<script>` (cari `const BRANDS = [`). Strukturnya:

```
BRANDS = [
  {
    id, name, tagline, color, bg, text, abbr, desc,
    logo?,   // opsional: path logo brand (versi untuk latar gelap); jika kosong → nama brand sebagai teks
    lines: [
      { name: "<nama line/seri>", products: [
        { id, name, model, category, emoji, hasVideo, desc,
          specs: { "Key": "Value", ... },
          photo?            // opsional: URL/path foto asli; jika kosong → pakai placeholder emoji
          photos?           // opsional: beberapa foto [..]; foto pertama jadi foto utama, tiap foto dapat thumbnail sendiri
          video?            // opsional: path video MP4 (H.264); diputar di thumbnail "Video" (butuh hasVideo:true)
          videoPoster?      // opsional: gambar sampul video untuk thumbnail & sebelum diputar
          price?            // opsional: harga jual umum (SRP) dalam rupiah, angka saja (mis. 4250000)
          priceUnit?        // opsional: satuan harga, mis. 'set', 'pcs', 'pair'
          eol?              // opsional: true = End of Line (tidak diproduksi lagi) → label EOL
          priceList?        // opsional: harga per varian, mis. { '1M': 2100000, '2M': 2600000 } (kabel per panjang) → kartu "mulai Rp …", detail tampil daftar
        },
        ...
      ]}
    ]
  },
  ...
]
```

- **Kategori** yang dipakai untuk filter: `Speaker`, `Subwoofer`, `Amplifier`, `DSP`, `Tweeter`, `Midrange`, `Cable`, `Accessories`.
- `color` = warna identitas brand (hex), dipakai untuk aksen & header kartu brand.
- Jumlah brand/produk/line di dashboard dihitung otomatis dari `BRANDS` (helper `brandProducts`, `brandCategories`).

### Cara menambah / mengubah data
- **Tambah produk:** tambahkan objek produk ke `products` pada line yang sesuai.
- **Tambah line:** tambahkan objek `{ name, products: [...] }` ke `lines` sebuah brand.
- **Tambah brand:** tambahkan objek brand baru ke `BRANDS` (wajib `id` unik, `lines`).
- **Tambah foto asli:** isi field `photo` pada produk dengan URL/path gambar (mis. `"assets/og-pc65.jpg"`). Foto otomatis muncul di kartu, halaman detail, dan di-embed ke PDF. Jika `photo` kosong, dipakai ikon emoji placeholder.
- **Tambah video:** simpan MP4 di `assets/`, isi `video` (dan `videoPoster`), set `hasVideo:true`. Kompres dulu agar ringan, mis.:
  `ffmpeg -i input.mp4 -vf scale=-2:720 -c:v libx264 -crf 24 -c:a aac -b:a 128k -movflags +faststart assets/<id>.mp4`
- **Logo brand:** simpan di `assets/brands/<id-brand>.webp` (latar transparan, ruang kosong dipangkas, versi **terang untuk latar gelap** — kartu brand & landing selalu gelap), isi field `logo`. Logo dipakai di strip brand landing, kartu dashboard, dan header halaman brand; ukurannya diseimbangkan otomatis oleh `fitLogo()`.
- **File media** disimpan di folder `assets/` dengan nama `<id-produk>.<ext>` (mis. `assets/ac-prow6c.jpg`).
- **Harga:** hanya **SRP** (harga jual umum, publik) lewat field `price` (+ `priceUnit`). Tampil di kartu produk (kanan nama), detail produk (`#panel-price`), dan menu Stok; **tidak** dicetak di spec sheet PDF. Produk tanpa `price`/`priceList` tidak menampilkan harga. Helper: `fmtRp()`, `srpText()`, `hasPrice()`. **Sumber harga saat ini:** daftar harga baru STEG & Audiocircle dari pemilik (Okt 2026; menimpa sebagian *Harga Baru* Form Gathering), selebihnya kolom *Harga Baru* Form Belanja Gathering CAI 2026. ML-C6.2/ML-C6.3 MKIII & ML-S10 tetap harga lama. IQ-M4C MB belum ada harga baru (masih 5.700.000). **EOL:** field `eol:true` → label oranye *EOL* (`eolTag()`) di kartu, detail (+ keterangan), dan menu Stok. Saat ini **tidak dipakai di produk mana pun** (label dihapus atas permintaan pemilik); fiturnya tetap ada bila dibutuhkan lagi. Satuan `priceUnit`: `pair` (bukan "pasang"; kabel RCA & K Series), `set` untuk semua Speaker/Midrange/Tweeter lain, `pcs`/`lembar`/`meter` sesuai sumber; kategori lain tanpa satuan. Di kartu produk harga tampil di baris sendiri di bawah model (`srpRow()`: label *SRP*/*Mulai* kiri, harga kanan) agar tidak bertumpuk dengan nama. Produk yang Harga Baru-nya "-" (mis. MS650, SST90, ML35, MZ650C TW, MS30, SS16, SQW-10) sengaja tanpa harga; produk Audio System memakai harga dari pemilik (Okt 2026: AS500.1 4.400.000, AS10 3.200.000, DSP-AS6 4.000.000, AY65 1.200.000/set, AY65C 1.700.000/set (diperbarui 14 Okt 2026)); harga gathering/diskon/cashback **tidak** dimasukkan. **Jangan** pernah memasukkan harga dealer/modal/diskon ke katalog — isi `index.html` bisa dibaca siapa saja.

## Sistem stok (Supabase)

Katalog tetap di `BRANDS` (GitHub); Supabase **hanya** menyimpan status stok per produk. Kode di blok `STOCK SYSTEM` di akhir `<script>`.

- **Project:** `portaldealer-stock` — URL & publishable key ada di konstanta `SUPA_URL` / `SUPA_KEY`. Key ini memang publik (aman di repo); akses tulis dibatasi RLS.
- **Tabel `stock`:** `product_id` (text PK, = `id` produk di `BRANDS`), `status` (`ready` | `indent` | `habis`), `note` (text), `qty` (integer ≥ 0, nullable), `incoming` (text, mis. `100 set` — barang OTW/belum datang), `updated_at` (auto via trigger).
- **RLS:** baca (`SELECT`) hanya user ter-autentikasi; tulis (`FOR ALL`, policy "Admin write") hanya `(auth.jwt() -> 'app_metadata' ->> 'role') in ('admin','editor')`. Policy Storage bucket `guides` memakai syarat peran yang sama. Tabel sudah masuk publication `supabase_realtime`.
- **Akun & peran:** semua akun dibuat di Supabase → Authentication → Users. Peran di `app_metadata.role` (di-set via SQL `update auth.users set raw_app_meta_data = coalesce(raw_app_meta_data,'{}'::jsonb) || '{"role":"<peran>"}'::jsonb where email = '<email>';`, lalu logout & login ulang): **`editor`** = pemilik/editor situs (`concertomediasby@gmail.com`), **`admin`** = admin staff (`concerto.stock@gmail.com`), kosong = **dealer** (hanya lihat). Editor & admin sama-sama boleh menulis stok & Panduan Dealer. Klien: `userRole()`, `isEditor()`, `isAdmin()` (= admin atau editor), label `ROLE_LABEL`. Konten situs (katalog, Academy, dll.) tetap dikelola lewat repo GitHub milik akun editor.
- **ID dealer bersama `CAI`** (keputusan pemilik): semua dealer login dengan satu akun `cai@dealer.concerto.id` (kode akses bersama). Konstanta `SHARED_DEALER_CODE = 'CAI'`: form login dealer hanya punya **satu kolom "Kode Akses"** (= password akun bersama, tidak peka huruf besar/kecil — input diubah ke HURUF BESAR, jadi password akun harus disimpan HURUF BESAR). Link *Login staff (email)* (`setLoginMode()`, `loginStaffMode`) menampilkan kolom email + password untuk editor/admin. Akun dibuat langsung di Supabase → Authentication → Users → Add user (Auto Confirm); ganti PIN lewat *Reset PIN* di Kelola Dealer atau SQL `update auth.users set encrypted_password = crypt('<KODE HURUF BESAR>', gen_salt('bf')) where email = 'cai@dealer.concerto.id';`. Konsekuensi: tidak bisa membedakan/memblokir dealer per orang; pesan WA tidak memuat nama toko. Sistem kode per dealer di bawah tetap berfungsi bila kelak dibutuhkan.
- **Login dealer = Kode Dealer + PIN:** dealer tidak butuh email. Akun dealer baru memakai email internal `<kode>@dealer.concerto.id` (`DEALER_CODE_DOMAIN`; tidak pernah dikirimi email, `email_confirm`). Di form login dealer mengetik kode (huruf besar/kecil & spasi bebas → `normDealerCode()`), `loginEmailFor()` mengubahnya ke email internal; isian yang mengandung `@` dipakai apa adanya (akun staff & akun dealer lama berbasis email tetap jalan). Kode 3–30 karakter `A-Z 0-9 -` (`validDealerCode()`); PIN acak 6 karakter tanpa huruf/angka mirip (`randomPin()`), minimal 6. Tampilan akun memakai `accountLabel()` / `codeFromEmail()`. Lupa PIN → Editor klik *Reset PIN* di Kelola Dealer.
- **Login dealer:** menu **Stok Produk** dan **Panduan Dealer** dikunci (`requireLogin()` di awal `openStockView()` / `openGuides()` → modal `#login-overlay`, `dealerLogin()`). Badge stok di katalog/detail juga hanya muncul setelah login (`loadStock()` tidak jalan tanpa login). - **Format data admin CAI** (didukung langsung): sheet stok gudang `No · Kode Barang · Data CAI · Baru · 2ND · FREE · PASANG · PINJAM` → qty diambil dari kolom **Baru** (stok baru siap jual; `Data CAI` = total semua kolom). Sheet OTW berjudul "BARANG BLM DATANG … (OTW)" dengan `No inv · Keterangan · Qty` ("100 SET", "40 FOC 2") → mode OTW mengisi `incoming` saja (stok tidak berubah; produk tanpa stok → `indent`; produk yang tak lagi ada di daftar OTW dikosongkan `incoming`-nya). No. invoice & FOC tidak ditampilkan ke dealer. Header boleh tidak di baris pertama; sheet, jenis data, dan kolom jumlah bisa diganti di pratinjau.
- **Sinkron Google Sheet** (sumber stok utama, pilihan pemilik): tombol *🔄 Sinkron Google Sheet* di panel admin (`syncFromSheet()`) mengambil CSV lewat endpoint `gviz/tq?tqx=out:csv` (`sheetCsvUrl()`, `parseCsv()`) lalu masuk ke pratinjau import yang sama → *Simpan*. Link sheet **tidak** ditaruh di kode (index.html publik, stok dikunci login) — disimpan di browser admin, `localStorage` key `cai-stock-sheet` (diminta sekali; *ganti link* di bawah tombol, `renderSheetLink()`). Sheet harus dibagikan "Siapa saja yang memiliki link — Pelihat". Sheet saat ini = STOCK DISTRIBUTOR (format di bawah); `gid` di link dipakai bila ada (pilih tab).
- **Format STOCK DISTRIBUTOR** (didukung langsung): sheet `DISTRIBUTOR` dengan `No · Merk · Unit · Stok Tersedia · Status` → kolom *Unit* = model, *Stok Tersedia* = qty (pemisah ribuan `3.425` dibaca 3425), *Merk* boleh singkatan brand (`AC`, `AS`, `DIOS`, …; nilai yang bukan brand seperti `ACC`/`MONA` diabaikan sebagai filter). Kode khususnya sudah dipetakan di `STOCK_ALIASES` (kabel per panjang & fuse per ampere dijumlah ke satu produk). OG: `AE` = Azure, `RF`/`REF` = Reference, `SUP` = Stream Line, `AP` = Red Dragon (konfirmasi pemilik). `SL-C6.2 MK IV` (non-S) diabaikan (`'-'` di `STOCK_ALIASES`) — hanya MK IV S yang dimasukkan. `AC2.2` = AC Sound Deadening; `DIOS1M–5M` = RCA Quadruple; `KQUAD/M` = Cable Quadruple; `DIOS0A/4A/8A` = Septuple 0G/4G/8G. Belum dipetakan (masuk *Produk Lain*): `ST10PRO` (produk berbeda dari `ST10P-PRO`, belum ada di katalog), DRC V4/V5, MSS1 PRO, SS-10, aksesori (grill/housing), brand MONA, dll.
- **Kode gudang ≠ model katalog:** peta tetap di `STOCK_ALIASES` (mis. `PL-*` → `PRO-*`, `HL-M2 MK II` → HL-M2, `SSF-1` → SFF1, `SSPDSP16II` → SS-DSP16 II). Kode lain dipilih admin di pratinjau dan diingat di `localStorage` key `cai-stock-alias` (`-` = abaikan).
- **Produk di luar katalog:** kode yang tidak cocok **default ikut disimpan** dengan `product_id` = `x:<KODE>` (`extraId()`, huruf besar, spasi dirapikan). Tampil di grup "Produk Lain (di luar katalog)" (`EXTRA_GROUP`, chip *Lainnya*) di menu Stok, panel admin, dan template; tanpa halaman detail. Hapus = set "— Belum diatur" di admin. Jika produk itu kelak ditambahkan ke `BRANDS`, petakan kodenya (alias) lalu hapus baris `x:` lamanya.
- **Deteksi OTW** hanya dari nama sheet atau baris judul di atas header (`looksOtw`), bukan dari isi data. Beberapa kode berbeda ke satu produk dijumlahkan (mis. kabel per panjang); kode identik berulang tidak dijumlah. Jika pilihan manual sering dipakai, pindahkan ke `STOCK_ALIASES`.
- **OTW di catatan:** pola `OTW CAI: 30 SET` / `OTW: 20 pcs` di Catatan dibaca sebagai barang OTW (`otwFromNote()`): saat import stok gudang ditulis ke kolom `incoming` (jika ada minimal satu OTW di file, produk lain di file itu dikosongkan `incoming`-nya), stok 0 + OTW → `indent`; data lama tanpa `incoming` tetap tampil OTW lewat fallback di `stockRow()`. Teks OTW dibuang dari catatan dealer karena sudah tampil sebagai 🚚 OTW.
- **Catatan untuk dealer:** `dealerNote()` membuang **FREE / PINJAM / 2ND / PASANG + angka** (di posisi mana pun, apa pun pemisahnya) kalimat "Tidak ada di template.", **nomor invoice** (`INV0241`, `(INV-0237)`, `No. Inv 12/A`) **FOC + angka**, dan nomor dokumen ber-garis-miring (`AC2026/00720`) sebelum ditampilkan ke dealer. Produk yang sedang OTW hanya menampilkan baris 🚚 OTW — catatan di bawahnya tidak ditampilkan ke dealer (menu Stok & detail) (menu Stok & detail produk). Catatan lengkap tetap tersimpan dan terlihat di panel admin. Tambah pola lain di array `DEALER_HIDDEN_NOTE` bila perlu.
- **Menu dealer:** view `stock` (`openStockView()`, `renderStockView()`) — publik, tanpa login.
- **Ubah skema:** jalankan SQL di Supabase → SQL Editor, **hanya statement baru** (editor menjalankan semua baris dalam satu transaksi; satu error membatalkan semuanya).
- Panel admin selalu gelap; warna teksnya dikunci eksplisit agar tetap terbaca di mode terang.
- Jangan tambahkan harga ke tabel stok.
